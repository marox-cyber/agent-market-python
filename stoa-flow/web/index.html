THE COUNTING RULES

One swap. One count.

  • Volume: the actual USDG amount on the input side, or the output side if USDG is not the input. USDG is treated as $1. Non-USDG pairs are unpriced, never silently assigned a historical dollar value.
  • Traders: distinct output recipients (to), not verified people. Relayers and contract recipients can affect this count.
  • Venues: venue1 and venue2 from each settled event. A venue is counted once per swap; old and new V4 adapters share the Uniswap V4 label.
  • Coverage: starts at deployment block 114,244,443. Refreshes retain a 64-block buffer and rescan 2,048 blocks for short reorganizations. This is not a finality guarantee.
  • Time: block timestamps, UTC. No wash swaps are created or removed; all settled activity, including team checks, remains visible.

Freshness & limitations
The dashboard requests an update every 60 seconds while open. Server results are cached for up to five minutes. If the public RPC fails, the last successfully collected snapshot remains visible with its original collection time and an explicit snapshot label. Failed refreshes wait five minutes before retrying; a 429 response is not immediately retried. A failed query never becomes a zero-volume result. The initial evidence was collected from Robinhood's official public RPC; live reads use Pocket Network and verify chain ID 4663.
Only the listed Stoa V1 router is covered. Direct venue swaps and independent contracts are outside this dataset. USDG-priced volume is a partial measure of total activity; pricing coverage is shown beside the metric. Raw token amounts are retained as integers in the evidence and CSV; display amounts use floating-point formatting.
This is an independent community project, not an official Stoa product. It does not connect a wallet, construct swaps, collect signatures or execute transactions.
